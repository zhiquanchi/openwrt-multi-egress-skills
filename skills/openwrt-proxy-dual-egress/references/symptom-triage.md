# 现象 ↔ 根因 对照表

Gemini 用不了的原因有六七种，**只有一种是双出口**。先把现象分类，再动手，能省掉大量瞎改。

## 一、现象速查

| 现象 | 最可能根因 | 处理方向 |
|---|---|---|
| 页面提示"检测到异常流量"，下面有 `IP 地址 A ≠ IP 地址 B` | **双出口 IP 割裂**（本 skill 主场景） | 方案 A/B，见 `fix-strategies.md` |
| 提示"Gemini isn't currently supported in your country/region" | 出口 IP 地区 OR 账号地区 | 换节点地区；账号侧改区 |
| 页面打不开、超时、连接被重置 | 节点不通 / DNS 污染 / QUIC 被拦 | 查节点延迟、DNS、关 QUIC |
| 能登录，发消息报错或转圈 | `generativelanguage.googleapis.com` 没走代理，或走了别的出口 | 把该域并入同一组 |
| 网页能用，API 返回 `403 PERMISSION_DENIED ... API Key` | 正常（没带 key），说明网络是通的 | 不是网络问题 |
| 偶发一次、刷新就好 | 会话/IP 临时抖动 | 观察；反复出现才动手 |
| 只在使用某些上游网络时出现（如切换 WiFi/网口后） | 多 WAN / 多上行，同一时刻走了不同上行 | 检查策略路由与 `ip rule` |

## 二、确认是"双出口"的三个证据

1. **页面上的两个 IP**：`A ≠ B` 已经是 Google 自证"看到两个出口"；
2. **规则侧**：`gemini.google.com` 与 `accounts.google.com` / `googleapis.com` 分属不同策略组；
3. **状态侧**：两个策略组的 `now` 指向不同节点（或一个是固定节点、一个是自动组）。

三个都成立 = 确诊。只有第 2 条成立时，先查第 3 条——两组可能碰巧选了同一个节点。

## 三、地区问题的判定（不要和双出口搞混）

Google 同时看两件事：

1. **IP 的地区与信誉**：看的是登录后的应用请求（`gemini.google.com/app`、后台 API 域名）来源 IP 在 Google 地理库中的归属与风险评分，而不是"首页能不能打开"；
2. **Google 账号的所属地区**：账号注册地 / 付款资料地区是中国大陆时，即使 IP 是美国也可能提示地区不支持。

判断顺序：

```sh
# 出口 IP 的地区
curl -s https://www.cloudflare.com/cdn-cgi/trace | grep -E '^(ip|loc)='
```

- IP 地区不对 ⇒ 先修分流/节点；
- IP 地区正确但仍提示 ⇒ 账号侧问题：首选注册新的当地账号；老账号可通过 `pay.google.com` → 设置（付款资料）→ 国家/地区 修改（有 Play 余额或活跃订阅时可能不可改，Play 商店地区一年只能改一次）。

典型误判：用 `curl` 测首页返回 200 就以为 IP 没问题——**未登录首页不经过完整的地区判定**。

## 四、DNS 与 QUIC

- **DNS**：如果 `dnsmasq` 把 `google.com` 解析成国内污染地址，连接会落到错误出口甚至直连。检查 `nslookup gemini.google.com 192.168.1.1` 与代理侧的 fake-ip / redir-host 配置是否一致。
- **QUIC（UDP/443）**：浏览器可能对同一域名走 UDP 与 TCP 两条链，如果 UDP 不经过代理（或走了另一条链），出口就会分裂。禁 UDP/443 是辅助手段，且要排除不应影响的网段，见 `fix-strategies.md` 末节。
- **IPv6**：VPS 或宽带的 IPv6 归属地可能与 IPv4 不同，导致同一会话出现 `IPv4 ≠ IPv6`（页面里就会显示成 `1.2.3.4 ≠ 2a09:bac5::`）。对策：强制 IPv4，或在代理侧统一处理 IPv6。

## 五、多上行（双 WAN / 双 WiFi / 办公网 + 家宽）

常见于"家庭宽带 + 公司 WiFi 双上行"的路由器：策略路由（`ip rule`）把某些网段强制走某个接口。这类环境里要注意：

- 同一台客户端的 DNS 查询与流量可能被送到不同上行；
- 给办公网段做 nft 例外（禁 QUIC、强制直连）时，**不要误伤**家庭网段，反之亦然；
- 排查时先确认客户端当前走的是哪个上行：`ip route get 8.8.8.8`、接口名（`phy0-sta0` / `phy1-sta0`）。

## 六、什么情况下本 skill 帮不上

- 出口节点本身被封（连接都不通）；
- 账号已被 Google 永久限制（表现为登录即失败，换 IP 无效）；
- 商业流媒体解锁问题（判定机制不同）。

这些应转去节点供应商或账号侧处理，不要在路由器规则上反复折腾。
